# Phase 2 Validation Evidence — Net-New Skill (Scripts Portability + Hermes MCP Registration)

**Date:** 2026-07-24
**Branch:** `multi-harness-poc` (worktree `trapezia-skill-validator-poc`)
**Plan:** `docs/superhuman/plans/2026-07-24-net-new-skill-phase2.md` (10 tasks, TDD).

Phase 2 proved the generator on a **genuinely net-new skill** — `policy-form-lister`,
a type-B (SKILL.md + scripts, no MCP) skill that never existed before this phase —
closing the two gaps the Phase 1 validation flagged. Full suite: **101 passed**.
mypy `--strict` clean on all touched files except the accepted, shared `yaml`
import-untyped gap (schema.py + generate.py).

## What was built (per task)

1. Schema: `Invocation.exec` (cli), top-level `bundle`, optional `usage`; validation branches on kind.
2. Generator: `skill_root(harness, spec)` + spec-driven `build_context(spec, harness)` with `{skill_root}` substitution.
3. Templates generalized — MCP section iff mcp invokes, Scripts section iff cli invokes, optional `usage` prose. No policy-check hardcoding remains.
4. `generate_mcp_registration(spec)` → the Hermes `mcp_servers.<name>` snippet (Gap 2).
5. CLI copies bundle files verbatim + writes the hermes-only snippet.
6. `policy-form-lister` fixture (real deterministic `list_forms.py` + glossary + spec); full `generated/**` regenerated.
7. Regeneration/drift test over all specs + bundle copies + snippet (drift-detection verified by mutation).
8. Additive linter rules: `spec.exec-token`, `spec.bundle-exists`.

## Gap 1 — scripts portability (live, all three harnesses)

One canonical `specs/policy-form-lister.yaml` emitted a working scripts skill for
every harness, with the **harness-correct `{skill_root}` exec path** and the
bundle (`scripts/list_forms.py` + `references/form-glossary.md`) copied verbatim.
Deployed and exercised against the same synthetic fixture (`sample_policy.txt`,
containing `CG 00 01 04 13`, `IL 00 17 11 98`, `CP 00 10`, `ACORD 25`, plus a
decoy `XY 12 34`). All three produced the identical, correct result:

```json
{ "forms": ["ACORD 25", "CG 00 01", "CP 00 10", "IL 00 17"], "count": 4 }
```

(The decoy `XY 12 34` is correctly excluded — `XY` is not a recognized line
prefix — and edition suffixes like `04 13` are stripped.)

**Result:** script-path portability is proven end-to-end — the same authored

The `policy-form-lister` demo skill is **left deployed** on OrionLab and HermesLab
as living evidence (parallel to policy-check in Phase 1). Per POC scope it is
**not** registered in any deployment tracker.

## Gap 2 — Hermes MCP registration snippet

The Hermes emitter now produces a committed, drift-checked
`generated/hermes/trapezia-commercial-policy-check/mcp_servers.snippet.yaml`:

```yaml
# Generated by trapezia-skill-gen - merge into the Hermes config.yaml `mcp_servers` mapping.
# Operator: point `command` at the skill's isolated venv interpreter if one is used,
# and adjust `cwd` to that venv/checkout as needed (Phase 0 F-6).
mcp_servers:
  trapezia-commercial-policy-check:
    command: python
    args:
    - -m
    - trapezia_commercial_policy_check.mcp_server
    env:
      GOOGLE_API_KEY: ${GOOGLE_API_KEY}
    cwd: ~/.hermes/skills/insure/trapezia-commercial-policy-check
```

Validated as parseable YAML. A **fresh** MCP-backed skill generated from a
canonical spec now ships a deployable registration fragment — the exact gap
Phase 1 left open (there, policy-check's registration only existed because Phase 0
had set it up manually). Delivery is **committed snippet + manual merge** (Chris's
decision): the operator merges it into `/opt/hermeslab/data/config.yaml`. The live
HermesLab config was **not** mutated during this phase — proving the emitter does
not require touching the running config.

## Templates de-hardcoded

`build_context` no longer flattens `invokes` to a single server, and the three
templates no longer contain policy-check literals. The former hardcoded
"call run_policy_check, then poll…" sentence now lives in the policy-check spec's
`usage` field. A cli-only skill renders a Scripts section and **no** MCP section;
an mcp-only skill renders an MCP section and **no** Scripts section (asserted in
`tests/spec/test_generate_scripts.py`).
